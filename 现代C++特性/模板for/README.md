# 模板 for (Template for)

模板 `for`（Template for）的正式名称是**展开语句 (Expansion Statements)**，是 C++26 引入的一项新特性。它允许在编译期对**大小可静态确定**的范围进行“循环展开”，把一段逻辑应用到多个（可能类型各异的）元素上，生成一系列独立的语句块

这项特性最初是为 C++20 设计的，但由于设计和可实现性方面的问题，最终被推迟到 C++26 才正式纳入标准。它被认为是 C++26 静态反 (Static Reflection) 的**核心基础设施之一**，用于展开 [`^^` 运算符](../猫耳运算符/README.md#展开元数据对象)获取的元数据对象

## 核心工作原理

- **编译期静态展开**：`template for` **不是**一个运行时循环。编译器会在编译期把循环体“复制粘贴”成一系列独立的语句块，不存在运行时的循环计数器、条件跳转，也**没有运行时开销**
- **独立作用域与异构类型**：每一次展开都有自己独立的作用域 `{}`。这意味着循环变量在每次迭代中**可以是完全不同的类型**（例如第一次是 `int`，第二次是 `std::string`），并且可以在内部直接使用 `if constexpr` 做编译期分支
- **支持控制流**：在展开的循环体内部，可以使用 `break`（终止整个展开）和 `continue`（跳过本次迭代的剩余部分），其效果等同于在展开后的对应代码块中执行这些跳转

## 语法

```cpp
template for ( 初始化语句(可选) 项声明 : 展开初始化器 )
    复合语句
```

- **初始化语句** (可选)：可以是表达式语句、简单声明（典型情况下是带初始化器的变量声明）或别名声明。**任何初始化语句都必须以分号 `;` 结尾**。
- **项声明**：只能是以下之一：
    - 简单声明（但只能有一个声明符，且不能有初始化器）。
    - 结构化绑定声明。
- **展开初始化器**：可以是表达式，或**花括号包围的逗号分隔表达式列表**（可带尾随逗号）。
- **复合语句**：任意语句块。

根据展开初始化器的语法和性质，`template for` 语句会落入以下三类之一：

1. **枚举展开语句**：展开初始化器是**花括号包围的表达式列表**。这等价于为列表中的每个元素生成一个独立的代码块
2. **迭代展开语句**：展开初始化器是**可展开迭代的表达式** (例如 `std::array`、`std::tuple` 或满足特定 `begin/end` 约定的类型)
3. **解构展开语句**：项声明是**结构化绑定**，用于直接解构可展开的类型

## 示例：打印任意数量、任意类型的参数

假设要实现一个 `print_all_data` 模板函数，允许接收任意数量、任意类型的模板参数。

### 传统递归实现

```cpp
void print_all_data() {}

template <typename First, typename... Args>
void print_all_data(First first, Args... args)
{
    std::cout << first << "\n";
    print_all_data(args...);
}
```

**痛点**：需要额外编写递归终止重载，代码啰嗦，且受限于递归深度（有栈溢出风险），同时会生成大量模板特化，拖慢编译速度

### 折叠表达式 (C++17)

```cpp
template <typename... Args>
void print_all_data(Args... args)
{
    ((std::cout << args << "\n"), ...);
}
```

这是目前最简洁的写法。但它本质上仍然是**基于运行时展开** (编译器会将其展开为 `a, b, c` 的逗号表达式)，在需要更复杂逻辑 (如包含 `if constexpr`、`break`/`continue`) 时不够灵活

### 模板 for (C++26)

```cpp
template <typename... Args>
void print_all_data(Args... args)
{
    template for (auto a : {args...})
    {
        std::cout << a << "\n";
    }
}
```

- `{args...}`：展开参数包，形成花括号包围的表达式列表，触发**枚举展开语句**
- 编译器会为列表中的每个元素生成独立的 `{}` 作用域，`auto a` 的类型在每次展开时独立推导

假设调用 `print_all_data(1, 3.14, "Hello World!");`，**编译期展开后**等价于：

```cpp
{
    auto a = 1;       // int
    std::cout << a << "\n";
}
{
    auto a = 3.14;    // double
    std::cout << a << "\n";
}
{
    auto a = "Hello"; // const char*
    std::cout << a << "\n";
}
```

这样既没有运行时循环开销，也避免了递归实例化带来的编译负担，代码可读性也更好

## 进阶说明

- **与 `if constexpr` 配合**：由于每次展开都是独立的代码块，你可以在循环体内根据当前元素的类型或常量值进行编译期分支：

    ```cpp
    template for (auto a : {args...}) {
        if constexpr (std::is_integral_v<decltype(a)>) {
            // 处理整数
        } else if constexpr (std::is_floating_point_v<decltype(a)>) {
            // 处理浮点数
        }
    }
    ```
- **与静态反射结合**：这是 `template for` 最重要的应用场景。通过 `^^` 运算符获取一个类型的成员列表，然后用 `template for` 遍历并生成对应的代码（如序列化、比较、打印等）
- **控制流的边界**：`break` 和 `continue` 是允许的，但要注意它们作用于**整个展开**，而不是像运行时循环那样“跳出当前迭代”。`return` 在展开体内使用是合法的，但如果在 lambda 内使用，需要留意返回类型推导的规则
